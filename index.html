The Narrator

Apr to Jul 2026

Master of Software Engineering capstone, built solo.

The problem

People rely on others’ experiences for choices like universities, employers, and airlines, but those stories are spread across many domain-specific apps. Reviews shrink them to star ratings, and few platforms show which content is trustworthy. The Narrator is one place to share structured real-life experiences in the form of narratives across domains, with community feedback and a transparent ranking.

What I built

A research-based, cross-domain experience-sharing platform, built as my Master of Software Engineering capstone using Design Science Research. It has a React front end and a Helidon MicroProfile backend: an API gateway with centralised JWT validation, five services, and a shared library. It supports personal and organisational accounts, helpful, thanks and not helpful reactions, follows, Kafka notifications, and a rank score that decays with time.

The result

Everything backend runs on one AWS EKS cluster in us-east-1: the gateway, five services, Kafka, and Postgres on an EBS-backed StatefulSet. A GitHub Actions pipeline pushes images to ECR (six repositories) and rolls them out. The React app is served from S3 and an ALB ingress fronts the cluster. Backend analysed in SonarQube at 80%+ coverage.

Cloud architecture on AWS

Hover or tap a step below to highlight it on the diagram. Scroll sideways on small screens.

  1. 1
    Users reach the app

    The React frontend is served from an S3 static website, and API traffic goes to the internet-facing ALB ingress over HTTP.

  2. 2
    ALB ingress to gateway

    The ALB forwards into the EKS cluster (us-east-1, Kubernetes 1.34, 3 t3.small nodes) and on to narrator-api-gateway.

  3. 3
    Gateway and five services

    The gateway (port 8088) validates JWTs (HS256) and routes by path to users (auth, profiles), narrative (stories), organisation (orgs, ranking), notification (email alerts), and community (follow graph). They share the narrator-commons library.

  4. 4
    Data layer

    PostgreSQL 15 runs as a StatefulSet with an EBS volume. Apache Kafka (KRaft) carries the narrative.published topic.

  5. 5
    GitHub pipeline

    A push to GitHub triggers GitHub Actions to build, test, and scan with SonarQube.

  6. 6
    Push to ECR

    Actions builds the Docker images and pushes them to AWS ECR, which holds 6 image repositories.

  7. 7
    Roll out to EKS

    Actions runs kubectl rollout so the cluster pulls the new images from ECR.

  8. 8
    Media and third parties

    An S3 media bucket stores images and photos. Gmail SMTP sends notification emails and SerpApi syncs Google Reviews.

The ranking formula, live

Narrative score = (H×2 + T×1 − NH×1.5 + R×1) × e−λ × days, with λ = 0.05. H is helpful votes, T thanks, NH not helpful, R average rating. Move the sliders to see it recalculate.

European Central Bank SPACE

2022 to 2025

The problem

Gigabytes of time-series data arrived from multiple sources through requests. It had to be verified, validated, and stored, then disseminated to destinations such as HDFS server environments and FAME.

What I built

Java Spring Boot backend services that verify and validate incoming time-series data and store it. Spark and Kafka pipelines on the Cloudera big data ecosystem (HDFS, YARN, Hive, HBase) disseminate it onward, and Kubernetes workloads keep the services highly available. I also fixed production issues.

The result

Remittance platform v4

2021 to 2022

Machnet Technologies. Middleware for sending and receiving money.

The problem

Getting a money transfer licence in the US is a big barrier. It costs a lot, and settlement has to be funded upfront, so smaller MTOs struggled to start offering international transfers.

What I built

Version 4 of the remittance middleware, an incremental upgrade of the legacy version 3, redesigned with microservice and event-driven architecture. It exposes APIs that MTOs plug into their own app or website. I also built the tier-based KYC module.

The result

An MTO launches with one API integration and builds its own app or website on top. The platform handles settlement through ACH, banks, and wallets, and payouts go to many payout organisations worldwide, by bank deposit or cash in hand.

RemitPulse, IRH and branchless banking

2018 to 2021

Citytech. Money transfer and banking systems built for Nepal.

The problem

Customers in the UK and Australia needed a reliable way to send money to Nepal, and people in rural Nepal had no bank branch nearby.

Branchless banking

A tablet-based bank for agents in rural Nepal. They open accounts, capture photos and biometrics (fingerprint and face), and send or pay out transactions. It connects to core banking through a middleware that speaks ISO messages, and admins see transactions, beneficiaries, and customers in a web portal. I also worked on the front end with PrimeFaces, JavaScript, and CSS.

RemitPulse

A remittance platform for UK and Australian customers sending money to Nepal. Payouts go through money transfer organisations, banks, or cash. It exposes APIs for mobile apps, POS devices, and third parties, settles in any currency, and has configurable beneficiary and transaction forms. I also built custom POS device apps.

International Remit Hub (IRH)

A remittance hub where multiple money transfer organisations call one set of APIs to send money around the world. I built the IRH APIs.
